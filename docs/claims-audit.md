## Review

Written by hand after reading the generated tables (bladed-85). The script finds numbers that exist **nowhere** in `results/`; it cannot show that a number
that does exist is the right one. Of 410 claims only 37 are matched by a specific value; the other 372 are in the last table for a human to read. Because a
common match proves nothing, the rest of this section checks by hand the ones that looked risky. Not checked: numbers inside pictures, the 372 weak matches
beyond the samples below, and integers without a unit (754 skipped, mostly counts such as slide numbers).

**Findings (the pitch is the Lead's, the deck the colleague's; nothing was edited):**

1. **Stale latency numbers, `pitch-script.md` line 327** ("median 0.0145, max 0.090, GPU single 0.2405 ms", source `results/ipp1-latency.md`). The file was re-measured
   and now holds: CPU single sample median 0.0145 ms, max 0.148 ms (1 thread) and 0.118 ms (4 threads), numpy max 0.087 ms; GPU (MPS) single sample median 0.2681 ms,
   0.4896 ms with the transfers that a real loop needs. **0.2405 and the max 0.090 are not in the file.** The script flagged 0.2405 only; the 0.090 passed as a common
   match, which is exactly the weakness described above. Fix: replace the row with the current values of `ipp1-latency.md`, or remove it.
2. **Two numbers had no file in `results/` and now have one.** "2 components carry 92.8 % of the variance" (cited as `Data-Brief.md`, which lives in the Obsidian vault, not in
   the repository) and "85 % of the discharges have an axis error below 1 mm, only three of 149 above 5 mm" (cited as computed from the viewer data). Both reproduce:
   92.78 % and 85.9 % (128 of 149; 3 above 5 mm), see the new `results/ipp1-claim-support.md` made by `analysis/ipp1_claim_support.py`. Fix: cite that file instead of
   `Data-Brief.md`; 85.9 % rounds to **86 %**, so "85" understates and does not match the shown digits. The definition matters and should be said once: the axis error of a row is
   the distance of the true and predicted axis, a discharge is judged by the mean of its rows (by the radial error alone it would be 92.6 %).
3. **Checked by hand and correct:** "27 times" for R axis on noisy input (10.15 / 0.377 = 26.9), "4.3 times worse" for 8 flux loops against all inputs (0.285 / 0.066), limited
   plasma "about 2.3 times worse" than divertor (R axis 0.553 / 0.237 mm in `ipp1-distribution.md`), camera 6 to 8 times worse on the axis (1.54 / 0.24 = 6.4 and 1.95 / 0.23 = 8.4 against
   the magnetic model on the same frames), 99.3 % `is_limited`.
4. **Wording to keep straight:** claims about the camera say 2 of 5 folds in `ipp1-camera-local-findings.md`; the cloud camera numbers are `cloud-camera-main.json` and are a separate
   measurement.

**Next for a stronger gate:** make every number on a slide carry its file name in the speaker notes (the deck has none), then a script can check each number against its own file
instead of against all of `results/`.
